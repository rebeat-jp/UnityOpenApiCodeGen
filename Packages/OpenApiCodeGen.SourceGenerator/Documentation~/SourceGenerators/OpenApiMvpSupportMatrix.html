OpenAPI support matrix

日本語版

Source Generator (Beta) による生成はベータです。 Source Generator generation is in beta. Review the supported features before use.

Editorの「Open Support Matrix」は、base packageに同梱したHTMLをブラウザーで開きます。 両パッケージにこの文書と参照資料のMarkdown／HTMLを同梱しており、公開タグやネット接続は不要です。 GitHub Actionsや外部仕様へのリンクを開く場合はネット接続が必要です。

目的と対象読者

この文書は、Rhycol.OpenApiCodeGen.SourceGeneratorで生成できるOpenAPI documentの 対応範囲を、API仕様の作成者とUnity利用者が判断するためのmatrixです。 対象はSource Generator providerで選択したlocal .json、.yaml、.yml document（extension case-insensitive）とHTTP(S) URLです。documentの版はSwagger 2.0（swagger: "2.0"）とOpenAPI 3.0／3.1／3.2です。Editorは参照グラフ全体を canonical Normalized Spec Bundle v2へ正規化し、Analyzerは1 specIdにつき1 AdditionalFile だけを読みます。Bundle v1はAnalyzerの後方互換入力として読み込めます。

生成器は、wire formatに影響する未対応要素を黙って省略または推測しません。 Unsupportedに分類された要素と、Partialの制約外へ出た要素は診断を報告し、生成を完了しません。 入力・bundle・definitionの診断OACG001–OACG009に加え、semantic generationではError OACG100–OACG106を使用します。型名の重複をsuffixで解消した場合はWarning OACG107を報告します。 意図して無視する要素（webhooksなどclientの呼び出しに無関係なもの、仕様上無視すべきheader parameterなど）は、wire contractを変えないWarning OACG108で報告します。 HTTP実装とJSONシリアライザーの選択と、必要なライブラリの不足はOACG010–OACG014で報告します（「Library選択（HTTPとJSON）」）。 診断IDごとの報告場面は「診断」、ギャップ別の最終状況と対象外の項目は「ギャップ別の最終状況」「対象外の項目」の節にまとめています。

Status 意味
Supported 記載した条件で生成・実行対象です。
Partial 記載した部分だけを生成します。条件外は診断となります。
Unsupported 対象外です。診断となります。

入力と参照

項目 Status 条件・制約
入力document Supported localの.json、.yaml、.yml file、またはHTTP(S) URL。local extensionはcase-insensitive。
OpenAPI version Partial 3.0.*、3.1.*、3.2.*、およびSwagger 2.0（swagger: "2.0"）のみ。3.2.*は3.1と同じJSON Schema 2020-12 dialectとschema規則で扱い、3.2で加わった項目は下の「OpenAPI 3.2」にまとめています。
OpenAPI 3.1 schema dialect Partial 既定または明示的なhttps://spec.openapis.org/oas/3.1/dialect/baseのみ（3.2はhttps://spec.openapis.org/oas/3.2/dialect/配下のOAS dialectも同様）。入口・外部完全OpenAPI文書のjsonSchemaDialectとschemaの$schemaで別dialectを指定するとOACG101、不正なURIはOACG100です。
Swagger 2 Partial swagger: "2.0"のdocumentを、OpenAPI 3.0へ正規化してから同じ生成pipelineで処理します（下の「Swagger 2.0」）。1.2など他の版はOACG101です。
URL入力 Supported public/private/loopback、cross-host redirectを許可。userinfo、空白、非HTTP(S)、HTTPS-to-HTTP direct/redirectは拒否。Generateが明示的なfetch/refresh操作で、Docker fallbackはありません。
private GitHub repository Supported https://raw.githubusercontent.comのURLのみ。SettingsのGitHub Tokenを、originが完全一致するリクエストとリダイレクト先にだけAuthorization: Bearerで送信。相対外部参照にも送信。トークンはプロジェクト外のユーザー設定に平文保存し、Bundle/manifest/診断には書き込みません。github.com、REST contents API、GitHub Enterprise Serverは対象外。
JSON/YAML semantic parity Supported 各normalizerがshared SpecNodeへ正規化し、同じsemantic/generation pipelineを通ります。
$ref Partial OpenAPI/Schema上の参照位置にあるinternal reference、またはEditorがBundle v2のedgeへ解決したexternal reference。example/default/enum/拡張データ内の同名キーはデータとして保持。fragmentはemptyまたはJSON Pointer。
external $ref Partial local external fileはreal/symbolic-link解決後もUnity project内。remote documentからlocal fileは不可。bare Schemaは可。参照先が完全なOpenAPI文書ならそのopenapi版とjsonSchemaDialectを検証し、入口とmajor.minor版が異なる場合はOACG101で拒否します。patch差は可。 Path Item $refの参照先がopenapi／swaggerを持たないbareなPath Itemファイルは、HTTP methodを持つか、$ref・parameters・servers・summary・descriptionだけを持ち、JSON Schema固有キーワード（type・properties・items・allOf・enum・requiredなど）を持たない場合にPath Itemとして内部の参照を収集します。1つでもschemaキーワードがあればbare Schemaです（$refだけのファイルはどちらでも同じ参照を収集します）。
unresolved / cyclic $ref Partial 解決できない参照はOACG102です。$refのaliasだけの循環（A→B→A）と、array／mapだけを経由して名前付きDTO／enumで閉じない循環はOACG103です。property・items・additionalPropertiesを経由するobject／enumの自己再帰・相互再帰は許可します。oneOf／anyOfのunionラッパーもobject・enumと同じ名前付きの型なので、unionを経由する再帰（Node: oneOf [Leaf, array of Node]など）も許可します。OACG104はBundle v1のexternal-reference互換診断です。
schema $ref target Supported schemaの$refは#/components/schemas/<name>に限らず、任意のJSON Pointer（例: #/components/schemas/A/properties/b、$defs配下、拡張キー配下）と、Bundle v2のexternal documentの任意fragmentを指せます。型名はpointer末尾のtokenから付け（末尾が配列indexなら直前のtokenを前置）、名前の衝突は既存どおり連番とOACG107で解決します。inline定義と同じschemaを指す参照は別の型になる場合があります。parameters／responses／requestBodiesなど他のcomponent参照は従来どおり#/components/<section>/<name>だけです。
URL query / fragment Partial queryはfetch identityに使いますが平文永続化しません。root URL fragment、userinfo、explicit file:は拒否。
URL format detection Supported final URL extensionとContent-Typeが既知なら一致必須。片方だけ既知は可、両方不明・競合は拒否。content sniffing/hintはなし。

Operations、parameters、responses

項目 Status 条件・制約
HTTP method Supported GET、POST、PUT、DELETE、PATCH、HEAD、OPTIONS、TRACE。OpenAPI 3.2ではQUERYとadditionalOperationsの任意のmethodも扱います（下の「OpenAPI 3.2」）。
servers Partial root serversは複数指定でき、各variables（default必須、enumは任意）も使えます。既定のコンストラクターはservers[0]の各variableをdefaultで置換したURLを使います（省略・空配列は/）。生成クライアントはpublic static IReadOnlyList<string> Servers（urlテンプレートの一覧）とpublic static string BuildServerUrl(int index, IReadOnlyDictionary<string, string>? variables = null)を持ち、展開したURLはbaseUrl引数として渡せます。BuildServerUrlは渡されたvariablesをenumで検証し、宣言のない名前・enum外の値はArgumentException、範囲外のindexはArgumentOutOfRangeExceptionです。urlの未宣言{x}はOACG101、defaultがenum外・空のenumはOACG100です。絶対URLはHTTP(S)のみで、FTPなどはOACG101です。//host/pathはHttpClient.BaseAddressのschemeで解決します。/pathと既定の/は同じoriginのrootから解決し、BaseAddressのpathとqueryを引き継ぎません。BaseAddressが必要な場合に未設定なら送信前にInvalidOperationExceptionです。明示的な空文字baseUrl overrideは相対URLとして扱います。相対server URLとoperation pathが/の場合、BaseAddressのqueryは1回だけ付加します。
path / operationのservers Partial operation、Path Item、documentの順に優先してserverを選びます。operationまたはPath Itemにserversがあるoperationは、その先頭serverの各variableをdefaultで置換したURLを使います。コンストラクターのbaseUrlはdocument levelのserversだけを置き換え、path / operationのserversは置き換えません。実行時に差し替えるには、public IDictionary<string, string> OperationServerUrls（キーは生成メソッド名、値は展開済みのserver URL）へ設定します。このプロパティは、path / operationのserversを持つoperationがあるクライアントにだけ生成します。候補が複数あっても使うのは先頭だけです。候補の一覧と展開はpublic static IReadOnlyList<string> GetOperationServers(string operationName)とpublic static string BuildOperationServerUrl(string operationName, int index, IReadOnlyDictionary<string, string>? variables = null)（BuildServerUrlと同じenum検証）で行い、operation名には生成メソッド名の定数を持つpublic static class OperationNamesを使います。OperationServerUrlsのキーは生成メソッド名です（他のメンバーとの衝突回避で連番が付くことがあるため、OperationNamesの定数を使ってください。未知のキーは無視されます）。OperationServerUrlsは最初の送信より前（構成時）に設定してください。スレッド安全ではありません。
server URL validation Partial 不正な絶対URL風・相対URL参照は位置付きOACG100、variablesに宣言のない{...}はOACG101です。不正な絶対URLを相対URLとして扱いません。有効なHTTP(S)・network-path・root-relative・path-relative形式は維持します。生のfragmentはoperation pathとの結合前に除き、エンコード済み%23はpath内に保持します。
parameter location Supported path、query、header、cookieのparameterを扱います。OpenAPI 3.2ではin: querystringも扱います（下の「OpenAPI 3.2」）。3.0／3.1のin: querystringは従来どおりOACG101です。
cookie parameter Partial Cookieヘッダーを1本にまとめて送信します（複数のcookie parameterは; で連結し、parameterの識別子順）。formstyleで、explodeの既定はtrueです。名前はRFC 6265のcookie-name（token）でなければOACG100、値はRFC 3986のunreserved以外をpercent-encodeします（cookie-octetの部分集合）。配列・objectはexplode: trueならname=a; name=b／k=v; k=w、falseならname=a,b／name=k,v,k,wです（区切りの,はOpenAPIのformどおりで、RFC 6265の厳密なcookie-octetには含まれません）。HttpClientHandler.UseCookies=true（既定）ではCookieContainerの値が手動のCookieヘッダーと併用・上書きされることがあるため、cookie parameterを使う場合はUseCookies=falseにするか、CookieContainerに値を入れてください（Unity / Monoでの上書き挙動は実機確認が必要です）。Cookieという名前のheader parameterとcookie parameterの併用はOACG101です。
Parameter Object fields Partial OpenAPI 3.0／3.1／3.2の標準項目とx-*拡張を認識します。requirdなどの未知項目は、path／operationのparameterや参照先でも位置付きOACG101です。schemaとcontentの併記はOACG100です。example／examples／allowEmptyValueは受理するだけで、送信値には影響しません。
parameter serialization Partial style／explodeは次の組み合わせを対応します。path: simple（既定）・label・matrix、query: form（既定）・spaceDelimited・pipeDelimited・deepObject、header: simple、cookie: form。explodeの既定はformだけtrue、deepObjectは省略時true（falseの明示は仕様未定義でOACG101）です。locationに無効なstyleはOACG100、プリミティブへのspaceDelimited／pipeDelimited／deepObject、配列へのdeepObject、spaceDelimited／pipeDelimitedのexplode: trueは仕様未定義のためOACG101です。任意parameterのnullは省略し、明示的な空文字列はname=（query）として送信します。allowEmptyValueは省略される値の代替を表し、明示的な空文字列には適用しません。
array / object parameter Partial OpenAPI 3.xの「Style Examples」表（color = blue,black,brown / R=100,G=200,B=150／空値／単一値）どおりに送信します（テストが表の全セルを検証します）。対象はプリミティブの配列（List<T>）と、プリミティブpropertyだけのobject（DTOまたはDictionary<string, T>）です。DTOは宣言したpropertyを名前の序数順にシリアライズします（nullのpropertyは省略）。additionalPropertiesがプリミティブのschemaなら、追加memberを宣言propertyの後にキーの序数順で続けます（値がnullのものは省略、プリミティブでない値はArgumentException）。additionalPropertiesが省略・trueの型なしopen DTOの追加memberは送りません。順序を指定したい場合はDictionaryを使ってください。配列要素のnullはArgumentExceptionです。空の配列・objectは何も送りません（pathは空文字列）。値の区切りとdeepObjectの[ ]は表のとおりそのまま出力します（|はSystem.Uriが%7Cにします）。header値はpercent-encodeしません。入れ子の配列・object、{}・JObject・union・複数型のparameterはstyleでは表せないためOACG101です（contentを使います）。
allowReserved Partial allowReserved: true（queryのみ）は、予約文字:/?[]@!$&'()*+,;=と既存の%XX（RFC 6570の予約展開）を値でエンコードしません。#は区切りとしてURLのfragmentになりHTTP層で落ちるため、常に%23にします。名前と、allowReservedでないparameterは従来どおりエンコードします。
parameter content Partial contentにはapplication/jsonまたは具体的なapplication/*+jsonを1件だけ宣言でき、値をJSON直列化してからpercent-encodeして送ります（path・query・cookieはpercent-encode、headerはエンコードなしでASCIIだけ）。schemaは任意（object・array・JToken・union可）です。style／explode／allowReservedの併記はOACG100、複数のmedia typeや他のmedia typeはOACG101です。
operationIdの省略 Supported operationIdのないoperationは、HTTP methodと、pathのセグメントを単語に分けたPascalCaseから決定的に命名します（{param}はBy＋名前）。GET /pets/{petId}はGetPetsByPetId、GET /はGetRoot、GET /report.{format}はGetReportByFormatです。ほかのoperationId（明示指定が優先）や同じ規則で生成された名前と重なる場合は、pathの序数順に2、3…を付けます。メソッド名としての衝突回避は通常の命名規則（AllocateUniqueName）が引き続き行います。明示したoperationIdの重複は従来どおりOACG106です。
Path Item $ref / components.pathItems Supported pathのPath Item $refはinternalと、EditorがBundle v2のedgeへ解決したexternal documentの両方を辿ります（#/paths/...、OpenAPI 3.1の#/components/pathItems/<name>、他ファイルのfragment。ref先がさらに$refでもよく、循環はOACG103）。$refと併記できるのはsummary／description／x-*だけで、operation・parameters・serversなどの併記は仕様上未定義のためOACG101です。参照先のoperationはその参照元のpath keyで検証・命名します。components.pathItemsは3.1のみ受理し（3.0はOACG101）、参照されたものだけを解析します。
enum parameter formatting Supported path／query／headerのstring enum値は専用のJson.NET serializerで宣言wire文字列へ変換し、ホストのJsonConvert.DefaultSettingsのconverterやcontract resolverを引き継ぎません。任意parameterのnull省略は維持します。
non-finite numeric parameter Unsupported path／query／headerのfloat／doubleにNaN・正負の無限大を渡すと、HTTP送信前にArgumentOutOfRangeExceptionです。任意parameterの省略と有限値は使用できます。
nested / untyped parameter Unsupported styleで表せないparameter（入れ子のarray/object、{}・JObject・union・複数型）は直接定義・多段$refともにOACG101です。contentを使うと任意のschemaを送れます。
required nullable parameter Unsupported path/query/headerのrequired: trueとnullableの組み合わせはOACG101です。参照チェーン全体を確認します。任意parameterのnull省略とDTOのnullableは維持します。
dot-only path segment Unsupported 引数置換後のpath segmentが.／..（1回percent-decodeした表現を含む）なら、HTTP送信前にArgumentExceptionです。.hidden、a.b、...や通常の複合segmentは使用できます。
path template braces Partial 対応しない{／}は位置付きOACG100です。/pets}や/pets/{id}}も生成時に拒否します。
path key delimiters Unsupported Pathsのキーに生の?・#があると、キーの位置でOACG100です。path内の文字ならpercent-encodeし、query値はquery parameterで宣言します。
header identity Supported header名だけ大文字小文字を区別せず、operation側で上書きします。送信名はoperationの宣言を保持し、path/query名は区別します。
header parameter name Partial HTTP field-nameのASCII tokenのみを許可し、空白・コロン・非ASCIIなど不正な名前はnameの位置付きOACG100です。
ignored header parameters Partial Accept、Content-Type、Authorizationは大小文字を問わず、OpenAPI仕様どおりparameterを無視し、名前の位置でOACG108のWarningを報告します。メソッド引数にもなりません。
header parameter value Partial 生成クライアントが受け付けるのはHTABと印字可能ASCII（U+0020～U+007E）だけです。CR・LF・DEL・非ASCII・サロゲートはHttpClient.SendAsyncより前にArgumentExceptionです。省略した任意値は送信しません。
content専用header parameter Unsupported Allow、Content-Disposition、Content-Encoding、Content-Language、Content-Length、Content-Location、Content-MD5、Content-Range、Expires、Last-Modifiedは大小文字を問わずOACG101で拒否します（Content-Typeは上の無視対象です）。独自のContent-*名まで一律には拒否しません。通常headerの追加に失敗した場合も実行時にInvalidOperationExceptionです。

string: minLength / maxLength / pattern Supported 長さはUTF-16のchar数ではなくUnicodeコードポイント数で数えます（サロゲートペアは1文字）。patternは部分一致（アンカーなし。固定するなら^・$）です。.NETのRegexを生成時に決めたモードで評価します。ECMA-262にない構文（原子グループ(?>・インラインオプション(?i)・\A \z \Z \G・文字クラス減算など）を含むpattern、またはECMAScriptモードで作れないpatternは、既定の.NET意味論（CultureInvariant。\d・\w・\sがUnicode対応）で評価し、そのpatternの位置でOACG108を報告します。それ以外はRegexOptions.ECMAScript（\d・\w・\s・\bがASCII基準でECMA-262に近い）です（両オプションは併用できないためモードは1つです）。差異: $は.NETでは末尾の改行の前にも一致します（ECMA-262は文字列末尾だけ）。ECMAScriptモードの\sはASCII空白だけで、NBSPなどのUnicode空白を含むECMA-262の\sより狭くなります。lookbehindと名前付きグループは.NETにもECMA-262（ES2018）にもありますが、ECMAScriptモードでは細かな挙動がedge caseで異なることがあります。どちらのモードでも作れないpatternは生成時に位置付きOACG100です。Regexは生成クラスのstatic readonlyフィールドとして1回だけ作ります（pattern単位で共有）。RegexOptions.CompiledはIL2CPPなどAOT環境でILを出力できないため使いません。照合timeoutは1秒で、超えるとRegexMatchTimeoutExceptionを内部例外に持つ通常の検証エラー（requestはArgumentException、responseはJsonSerializationException）です。length／patternの対象はstring、format: byte（base64文字列）、uuidです。date・date-timeのstringはrequestでは日付型として直列化されるため長さとpatternを検査しません（応答は文字列として検査します）。XML docにMust be 3..50 characters.のような制約文を出力します。

object: minProperties / maxProperties Supported JSONのmember数を検査します。open DTO（[JsonExtensionData]）は宣言propertyと追加memberの合計、Dictionary<string, T>とfree-form object（JObject）はその要素数です。requestではシリアライズ後のJSONを数えるため、readOnly propertyと未設定のoptional propertyは含みません。
patternProperties / propertyNames / dependentRequired（3.1） Partial patternPropertiesは、名前がpattern（部分一致）に一致するmemberの値をそのschemaで検査します（宣言propertyにも適用。mapとopen objectの追加memberの型は変わりません）。propertyNamesは各memberの名前を、dependentRequiredは「指定propertyがあれば列挙したpropertyも必要」を検査します。メッセージに含めるkeyは32文字に切り詰めます。subschemaが自分自身を（DTOを介さずに）参照する循環はOACG103です（DTOを介する再帰は可）。allOfの各partが持つobject用のキーワード（minProperties・maxProperties・patternProperties・propertyNames・dependentRequired）は部品ごとに保持し、すべて満たす必要があります。

検証の範囲と例外 Partial requestは送信前に検証し、違反はArgumentException（ParamNameはparameter名またはbody引数名）でHTTPは送信しません（fake handlerは呼ばれません）。対象はJSON body（入れ子のDTO・配列要素・map値を含む）、form-urlencodedとmultipartのfield（ファイル以外）、text body、parameter（path・query・header・cookie・content）です。responseは受信時に検証し、違反はJsonSerializationExceptionです。対象はJSON本文、response header、text本文で、oneOf／anyOfの候補判定とnotの判定にも制約が効きます（制約で候補が決まります）。メッセージにはパス（$.items[2].name）とkeywordを含め、値そのものは含めません。readOnly propertyはrequestで検証せず、writeOnly propertyが応答に欠落しても許可します（存在すれば検証します）。securityの資格情報は対象外です。メッセージのパスにはmember名（データ由来）が入りますが、値やpropertyNames違反のkeyは含めません。検証が行わない・制限される箇所のまとめ: requestではnotとunion（oneOf／anyOf）の候補値の制約を評価しません（応答だけ）。oneOf／anyOfと同じschemaに併記した検証キーワードはOACG101です（メンバー側へ移す）。uniqueItemsは1と1.0を同じ値とみなします。
const Partial OpenAPI 3.1のscalar const（string／integer／number／boolean）。成功応答では値の一致を検査し（integer／numberは数値として比較するため2.0は2と等価）、不一致はJsonSerializationExceptionです。request DTOでは、string／整数／浮動小数／decimal／booleanのDTO propertyの初期値になるだけで、request側で値は検証しません（nullableな任意propertyは初期値の対象外）。object／array値はOACG101、schema型と合わない値はOACG100です。nullや単一のscalar型を持たないschemaのconst、enumと併記したconstはOACG108で無視します。
description / title / deprecated / default Supported titleとdescriptionはDTO・property・enum（とmember）のXML docへ出力します。deprecated: trueはschemaとpropertyに[Obsolete]を付けます（生成コード内は#pragma warning disable CS0612, CS0618）。defaultはXML docだけで、wire contractは変えません（object／arrayのdefaultは無視）。operationのdeprecated: trueは生成メソッドへ[Obsolete]を付け、summaryは<summary>、descriptionは<remarks>に出します。parameterのdeprecatedとdescriptionは<param>のXML docに反映します（C#の引数には[Obsolete]を付けられません）。
allOf Partial 各partのproperties・required・additionalPropertiesを1つのsealed DTOへ平坦化します（$ref先は再帰的に展開し、入れ子のallOfも可）。requiredは和集合です。closednessは合成後に評価します。どれか1つのpart（または3.1の$refsiblings）がadditionalProperties: falseならDTO全体をclosedにし、許可するpropertyは全partのpropertiesの和集合です（partごとのfalseを単純合算して、他のpartのpropertyを拒否することはしません）。additionalPropertiesがschemaのpartがあればtyped open（複数あれば同じschemaが必要）、それ以外はopen objectです。同名propertyの型がpart間で異なればOACG101（2つ目の宣言の位置、1つ目はadditional location）、同じ型なら統合します。partがobject以外のtype・items・enum・constを持つ場合、partがoneOf／anyOfを持つ場合（discriminator付きのbaseを除く）はOACG101、どのpartも宣言しないrequiredはOACG100、allOfの循環はOACG103です。part内のnotはOACG108で無視します。allOf: [ {$ref} ]の1要素にdescription・nullableなどの注釈だけを併記する定番の形は、新しい型を作らない参照です（nullableも保持）。
oneOf / anyOf + discriminator Partial discriminator付きのoneOf／anyOfは、sealedなunionラッパークラス（例: Pet）とメンバーのDTO（Cat、Dog）を生成します。メンバーのDTOはラッパーを継承しない通常のsealed DTOです。ラッパーに付けるJsonConverterが具象DTOの書き出しで再入して無限再帰することはありません。ラッパーはFromCat(Cat)・暗黙変換・TryGetCat(out Cat)・AsCat()、保持している具象値Value、選択値DiscriminatorValueを持ちます。メンバーは$refでobjectを指す必要があります（inline、またはobject以外は、メンバーの位置のOACG101）。discriminator値はmapping（値はschema名、#/components/schemas/Xのinternal pointer、またはoneOf内の$refと同じ文字列）と、mappingのないメンバーの暗黙値（schema名）で解決します。メンバーにmappingがあればその値だけが有効で、複数あれば最初の値を送ります。他ファイルを指すmapping、メンバーでないschemaを指すmappingはOACG101、複数のメンバーに同じ値を割り当てるとOACG100です。メンバーDTOがdiscriminator propertyを宣言していなければ生成側が任意のstring propertyとして追加し、選択値が1つならDTOの初期値にします（宣言済みのstring propertyにも同じ初期値を付けます）。この初期値は検証せず、requiredにもしないため、unionを経由しない単独利用のDTO（discriminatorを持たない応答など）は有効なままです。discriminatorの有無と値の検査はunion（converterと成功応答の契約検査）だけが行います。requestはunionが常に選択値を書きます。成功応答は値でメンバーを選び、未知・欠落・stringでない値はJsonSerializationExceptionで、選んだメンバーのDTO検査（closedなら未宣言property、必須property）も行います。ラッパーのJsonConverterクラスにはIL2CPP用のPreserveAttributeを付けます。
discriminator付きbase（継承） Partial oneOf／anyOfを持たずdiscriminatorだけを持つschema（子がallOf: [ {$ref: base}, … ]で継承する形）は、mappingの対象と、同じdocumentのcomponents.schemasでallOfにbaseを直接$refしているschema（孫まで）をメンバーとするunionになります。baseのpropertiesは子のDTOへallOfで平坦化されます。base自身は（値がPetなどでも）メンバーにならず、そのdiscriminator値は未知の値として拒否します。子もmappingもないdiscriminatorはOACG108で無視します。他のdocumentのschemaは子として探しません。oneOf＋discriminatorを持つschemaを子がallOfで継承する形では、子はそのschemaのpropertiesだけを引き継ぎ、oneOfは引き継ぎません。
oneOf / anyOf（discriminatorなし） Partial type: nullだけの部品を除いた候補が1つなら、その型のnullableに正規化します（[X, null]）。それ以外は成功応答の生のJTokenを保持するunionラッパーです（FromJToken(JToken)、ToJToken()、候補ごとのFromX(T)・暗黙変換・TryGetX(out T)・AsX()。string／integerなどのプリミティブ候補も扱います。アクセサ名は型名で、String、Int32、CatListなどです）。成功応答は候補ごとに既存のJSON契約検査を試し、oneOfはちょうど1件、anyOfは1件以上の一致を求めます（違反は一致件数つきのJsonSerializationException）。一致は構造検査（型、closed DTOの未宣言property、必須property、enumの値、const）で決めます。oneOfで複数の候補が一致した場合は、応答JSONのすべてのpropertyを宣言している候補（closedとみなした一致）に絞り込み、ちょうど1件ならそれを選びます（open DTO同士が重なる典型ケース）。絞り込んでも1件にならなければエラーです。integerとnumberのように区別できないoneOfや、同じpropertyだけを持つ候補は失敗し得るので、required・additionalProperties: false・discriminatorで区別できるようにしてください。anyOfは絞り込まず1件以上の一致で足ります。TryGetXも同じ規則で候補を選びます。TryGetXは、FromXで渡した値か、保持しているJSONをJson.NETの厳密な設定（未宣言memberはエラー）で変換できるかで判定します。requestは渡された候補値またはJTokenをそのまま直列化します（候補値のrequest検査は行いません）。同じschemaへproperties／requiredなど形を決めるkeywordを併記する、allOfとoneOf、oneOfとanyOfを併記する場合はOACG101です（keywordはメンバー側へ移します）。unionのparameterもOACG101です。
not Partial 成功応答の検査だけで評価し（notのschemaに一致した値をJsonSerializationExceptionで拒否）、生成する型は変えません。schema・property・$ref先のどこのnotも対象で、一致は構造検査（型、enum値、const、DTOの形）で決めます。requiredだけのような形を持たないnot、boolean schema、再帰するnot、未対応の要素を含むnotは、全値を拒否してしまうか判定できないためOACG108で無視します。requestでは評価しません。
readOnly / writeOnly Supported readOnlyなDTO propertyはrequestへ送信せず（生成されるShouldSerialize<Name>()がfalse）、requestのrequired検査からも外します。成功応答ではschemaのrequiredどおり必須です。writeOnlyなpropertyは成功応答で欠落しても許可し、requestではrequiredのままです。$ref先のschemaに付いたreadOnly／writeOnlyも、参照するpropertyに適用します。readOnly propertyの値はrequestで検証もしません。Unity IL2CPPのmanaged strippingでreflection専用メンバーが削除されないよう、ShouldSerialize<Name>()とAdditionalPropertiesにはinternalなPreserveAttributeを付け、ShouldSerialize<Name>()はEditorBrowsable(Never)にします。
format: byte Supported byte[]（Json.NET標準のbase64）へmappingします（従来はstring）。成功応答は文字列かつ有効なbase64であることを検査し、path/query/header parameterは標準base64文字列で送ります。
format: binary Partial multipartのファイルpart（<ApiName>FileParameter）、バイナリのrequest本文（byte[]）、バイナリ応答（byte[]）で使えます。JSONの本文・DTO（JSON応答を含む）・parameter・header・form-urlencodedの値で参照されると、binaryのschemaの位置でOACG101です（binaryを含むschemaをcomponentsに置くことは可能で、使われた場所で判定します）。3.1のtype: string＋contentMediaType（contentEncodingなし、JSON・text・xml以外）も同じ扱いです。大文字小文字の違うformatは従来どおり通常のstringです。

$refと併記できる注釈・データのキーは$comment、default、deprecated、 description、example、examples、externalDocs、readOnly、summary、title、writeOnly、xml、x-*です。 OpenAPI 3.0では既存互換としてnullableも扱います。

リクエストJSONのformat: dateはyyyy-MM-ddへ変換します。公開型のDateTimeは維持し、 date-timeのDateTimeOffsetにはdate用converterを適用しません。

OpenAPI 3.2

OpenAPI 3.2のdocument（openapi: 3.2.*）は、3.1と同じJSON Schema 2020-12 dialectとschema規則で処理します。3.2だけの項目は3.0／3.1では従来どおり診断になります（queryはOACG101など）。

tagsのparent／kind／summary Supported ドキュメント専用で、生成コードは変わりません。形式（文字列）と、parentが宣言済みのtagを指し循環しないことだけを検証します（違反はOACG100）。tag名の重複もOACG100ですが、これは3.2だけの検査で、3.0／3.1では検査しません。

media typeのitemSchema Partial streaming（SSEと逐次処理）は対象外です。text/event-streamにitemSchemaがあればOACG101、順次media type以外（application/jsonなど）のitemSchemaもOACG101です。application/jsonl・application/x-ndjson・application/ndjson・application/json-seq・application/geo+json-seqのitemSchemaは解釈せずOACG108で通知し、本文は従来どおりbyte[]（binary）です（itemごとの読み取りは行いません）。itemSchemaは解析しないため、その中の$refはEditorも収集せず、DTOも生成しません。Media Type ObjectでencodingとprefixEncoding／itemEncodingを併記するとOACG100です（仕様上の禁止）。単独のprefixEncoding／itemEncoding（Media Type Object）と、Encoding Objectの入れ子のencoding／prefixEncoding／itemEncodingはOACG108で無視します。itemSchemaは3.0／3.1では従来どおり未知の項目として無視します。
discriminatorのdefaultMapping Supported discriminatorの値がmappingのどれにも一致しない、またはdiscriminatorの項目がない・文字列でないときに使うメンバーです。値はスキーマ名または参照で、oneOf／anyOfのメンバー（継承形のbaseでは子または参照先のschema）でなければOACG101です。変換器は該当するJSON objectをそのメンバー型へ読みます（応答の契約検査も同じ。メンバー自身のschemaに合わない本文は従来どおり拒否します）。指定がなければ、従来どおり未知の値はJsonSerializationExceptionです。書き出す値はそのメンバーの最初のdiscriminator値で、読んだ未知の値は保持しません。3.0／3.1では従来どおり無視します。

Swagger 2.0

Swagger 2.0のdocument（swagger: "2.0"）は、意味解析の前にOpenAPI 3.0（3.0.3）の等価なtreeへ正規化してから、3.0と同じ処理（parser、生成model、出力、診断、実行時検証）に渡します。専用の生成器はなく、生成されるクライアントは、同じ内容を手で書いたOpenAPI 3.0 documentのものと一致します。YAMLのSwagger 2.0も同じです。openapiとswaggerを併記したdocument、"2.0"以外のswaggerの値（"1.2"、数値の2.0など）は、swaggerの位置でOACG101です。

Generated outputと利用上の制約

生成結果は次のpublic API contractです。

  • public mutable sealed DTO（Newtonsoft.JsonではJson.NETのattribute、System.Text.JsonではSystem.Text.Jsonのattributeを使用）
  • 任意かつschema上nullableなDTO propertyの<PropertyName>Specifiedによる存在状態の管理
  • 任意かつschema上nullableなrequest bodyの<BodyParameterName>Specifiedによる明示的なJSON null送信
  • 宣言したwire文字列を完全一致で扱うstring enum converterとList<T>
  • oneOf／anyOfのsealed unionラッパークラス（FromX／TryGetX／AsX、discriminatorなしはFromJToken／ToJToken）と、internalなJsonConverter
  • injected HttpClientを使うasync client API。documentまたはexplicit base URLを指定するconstructorを使用可能（UnityWebRequestを選んだclientはHttpClientの代わりにbaseAddressを受け取ります）
  • path/query/header/body、JsonConvert、CancellationToken、宣言された2xx response handling
  • request本文のmedia type別メソッド（<name>AsMultipartなど）、ファイルpartの<ApiName>FileParameter、status別の結果型<OperationName>Response、<name>WithHttpInfoと<Name>HttpInfo
  • generated <ApiName>Exception（Error／TryGetError<T>／ErrorDeserializationExceptionを追加）

生成モデルは、raw JSON/YAMLを各normalizerでnormalized bundleへ変換した後、OAS semantic parserとinternal reference resolverを通し、 Roslyn非依存のgeneration modelを作ってから、Roslynでparseしたdeterministic source emitterへ渡します。 emitterの結果をAddSourceします。JSONシリアライザーとHTTP実装は、client定義のJsonSerializer／HttpTransportでclientごとに選びます。 既定はNewtonsoft.JsonとSystem.Net.Http.HttpClientで、この文書の他の節は既定の出力を前提にしています（選択肢と差異は「Library選択（HTTPとJSON）」）。 Docker providerは別providerであり、fallbackまたは切替は行いません。

生成物はhand-editするsourceではなく、再Generateされるpublic contractです。spec IDを含むhint nameは stableで、generated nameはordinalのdeterministic namingとsuffixによるcollision resolutionを使用します。 複数specでDTO名が重なる場合は、generated namespaceを分けてください。current generated typeは namespace-levelのため、同じnamespaceには共存できません。

apiNameが生成クライアントの固定メンバー名と一致するとOACG005です。予約名は _httpClient、_baseUrl、DateOnlyJsonConverterInstance、CreateRequestUri、 CombineAbsoluteUri、CombinePaths、CombineQueries、AppendQuery、 SplitPathAndQuery、ValidatePathSegments、CreateJsonContent、 ConvertToString、DateOnlyJsonConverter、ReadJsonResponseBodyAsync、HasPreamble、 Servers、BuildServerUrl、ExpandServerUrl、OperationServerUrls、 ResolveOperationServerUrl、OperationNames、GetOperationServers、 BuildOperationServerUrlです。UnityWebRequestを選んだclientでは、次のメンバー名も予約名で、apiNameが一致するとOACG005です: _baseAddress、RequestTimeout、ConfigureUnityWebRequest、SendUnityWebRequestAsync、 SetUnityRequestHeader、AddUnityResponseHeader（HttpClientのclientで受理される名前は変わりません）。

生成するDTO・enumのwire converter・unionと、そのpropertyには、IL2CPPのManaged Stripping Level Highでもリフレクション専用のmemberを残すため、 internalなPreserveAttributeを付けます。attributeはclientごとに専用のnamespace <generated namespace>.<ApiName>_Preserveへ宣言します （同じnamespaceに複数のclientを生成しても重複しません）。DTO・enum・unionのないspecでは生成しません。 同じnamespaceに利用者が<ApiName>_Preserveという名前の型を宣言すると、このnamespaceと衝突してコンパイルエラーになるため、別の名前にしてください。 この変更により、DTOまたはenumを持つspecの生成出力は、既定の組み合わせでも変わります（attributeの追加と、PreserveAttributeの宣言先がclientのnamespaceから<ApiName>_Preserveへ移ったこと）。 Schema members whose CLR names would match another member's Name + "Specified" are assigned a unique CLR name while retaining their JSON wire names. This prevents Json.NET from mistaking a schema boolean for a presence flag.

Library選択（HTTPとJSON）

System.Text.JsonとNewtonsoft.Jsonの差異

生成するpublic APIの形は同じで、次の点が異なります。それ以外の契約（wire形式、制約の検証、診断）は同じになるよう実装し、 両方のシリアライザーで同じ種類のテストを実行しています。

項目 Newtonsoft.Json System.Text.Json
{}・任意の値（Any） JToken JsonElement
propertiesのないtype: object（FreeObject） JObject System.Text.Json.Nodes.JsonObject
open DTOの宣言外member（ExtensionData） [JsonExtensionData]のIDictionary<string, JToken> [JsonExtensionData]のIDictionary<string, JsonElement>
discriminatorなしunionの生の値 FromJToken／ToJToken FromJsonElement／ToJsonElement（FromJsonElementで作った値は既定のoptionsで読むため、clientのconverterは適用されません）

宣言したエラー本文（Error、TryGetError<T>） 検査せずそのまま逆シリアル化。失敗はErrorDeserializationException 先に成功本文と同じ検査（重複名、closed DTOの宣言外member、整数の字句、enum値、必須member）を行います。失敗するとErrorはnullで、理由はErrorDeserializationException

UnityWebRequestのclientは、request・response・検証の経路をHttpClientのclientと共有し（HttpRequestMessage／HttpContent／HttpResponseMessageを使うアダプター方式）、 最後の送信だけをUnityWebRequestで行います。constructorはHttpClientの代わりにUri? baseAddress（と任意のbaseUrl）を受け取ります。
